# 포트폴리오 디자인 방향 · v4

## 이번 수정

자기소개 → 경력/프로젝트/논문 → 개별 상세의 정보 구조를 유지하고, **작업 미리보기와 사용자 반응을 중심으로 한 쇼케이스**로 변경했습니다.

- 홈: 이름과 짧은 소개, 큰 작업 표지, 세 개의 섹션 링크.
- PC: 마우스에 반응하는 표지의 기울기와 깊이, 탭·화살표로 작품 전환.
- 모바일: 소개 바로 아래에 섹션 목차, 그 다음 큰 미리보기. 탭·스와이프로 작업 전환.
- 프로젝트·논문 목록: 큰 이미지 표지를 앞에 두고 역할·설명을 짧게 배치.
- 상세: 제목·표지, 담당 역할 2개, 핵심 결과와 조건, 펼쳐보는 전체 설명.

## 시각 방향

밝은 바탕에 큰 세리프 이름과 산세리프 본문을 유지하고, 시각적인 중심을 한 개의 큰 작업 표지로 옮겼습니다. 연보라의 음성 AI, 사진 콜라주를 활용한 이미지 검색, 진한 파랑의 연구 표지를 겹쳐진 인쇄물처럼 구성했습니다. 목록에서는 기사 추천·의류 검색·위치 기반 검색과 연구별 표지를 구분합니다.

표지의 사진은 라이선스가 허용된 Unsplash 이미지이고, 레이아웃·SVG·매개변수 기반 와이어 패턴은 직접 작성했습니다. 회사의 실제 운영 화면이나 실험 데이터 그래프가 아닙니다. 화면에 ‘프로젝트 소개용 표지’를 표시하고 원본 사진·라이선스를 `assets/images/README.md`에 기록했습니다.

## 동작

| 조작 | 반응 |
| --- | --- |
| PC에서 표지 위로 마우스 이동 | 좌우 최대 약 7도·상하 약 5도의 기울기. 벗어나면 원래 위치로 복귀 |
| 미리보기 탭·이전/다음 버튼 | 표지·제목·관련 수치·실제 상세 링크가 함께 변경 |
| 홈 섹션에 hover·키보드 focus | 해당 분야의 작업 미리보기 표시 |
| 표지 클릭 | 해당 경력 단계나 프로젝트·논문 상세로 이동 |
| 모바일에서 가로 스와이프 | 이전/다음 작업으로 전환. 세로 스크롤은 유지 |
| 미리보기에서 좌우/Home/End 키 | 작업 선택 및 포커스 이동 |
| 섹션·상세 이동 | 짧은 진입 전환. 실제 해시 주소·뒤로가기 유지 |
| 목록 스크롤 | 화면에 들어오는 항목을 한 번만 부드럽게 표시 |
| 시스템의 동작 줄이기 설정 | 기울기와 진입·장식 애니메이션 없이 같은 콘텐츠·조작 제공 |

자동으로 계속 넘어가는 캐러셀과 무한 배경 애니메이션은 사용하지 않습니다. 음성 표지의 막대 효과는 짧은 유한 반복입니다. 이벤트·관찰자·진행 중 애니메이션은 화면 전환 시 정리합니다.

## 읽기 기준

- PC 본문 18–20px, 모바일 17–18px.
- 메뉴·날짜·상태·측정 조건도 최소 17px.
- 작은 표지에서는 보조 그래픽 문자를 숨기고 실제 의미·수치는 HTML 설명으로 표시.
- 기본 화면은 발표형 요약, 전체 구현·실험 조건은 펼쳐보기.
- 운영 관측·통제 실험·미배포 PoC 구분은 기본 결과 설명에도 표시.
- 영어 기본, EN/KOR 전환 시 현재 상세·작업 선택·펼침 상태 유지.

## 구현 파일

- `styles.css`: 기본 레이아웃·읽기 크기.
- `editorial.css`: 로컬 폰트·색·공통 타이포그래피.
- `showcase.css`: 작업 미리보기·이미지 목록·반응형·모션 스타일.
- `visuals.js`: 직접 작성한 작업 표지와 미리보기 마크업.
- `motion.js`: 작업 전환·포인터·터치·키보드·진입 효과와 정리.
- `script.js`: 기존 화면 계층·언어·상세 데이터 연결.
- `scripts/smoke.py`: 레이아웃·텍스트·기존 기능과 인터랙션 검증.
- `scripts/record-demo.py`: 실제 브라우저 조작 영상 기록.

## 참고 자료와 한계

[레퍼런스 검토](design-references.md)에 실제로 확인한 자료를 구분했습니다. 제공된 X 영상과 공개 개발자 자료를 읽었지만, Behance의 지정 검색 경로는 재확인에서도 403 브라우저 확인 응답을 반환했습니다. 일반 검색엔진에서도 이번에 신뢰할 수 있는 개별 작품 자료를 확보하지 못했습니다. 보지 못한 Behance 작품을 선택·복제했다고 설명하지 않습니다.

따라서 v4의 표지와 모션은 **사용자의 ‘시각적으로 풍부하고 반응하는 포트폴리오’ 요구를 구체화한 독자 시안**입니다. 합격 여부·채용 효과에 관한 미확인 주장을 추가하지 않았습니다.

## 배포

HTML/CSS/JavaScript만으로 실행하며 새 런타임 의존성은 없습니다. 폰트와 사진은 로컬 자산이라 방문자가 외부 리소스 서버에 접속할 필요가 없습니다. GitHub는 코드 백업, Vercel은 향후 배포 방향이며 실제 공개 배포는 수행하지 않았습니다.
